# SwapContract

The SwapContract is the thin swap layer that connects the protocol to external markets. The router uses it for stablecoin↔vault-asset swaps; the strategy allocator uses it to convert reward tokens into the vault asset. No other contract can call it.

The contract is deliberately thin. It does not choose what to swap, when to swap, or hold funds between calls. It validates the swap target, executes the call, and returns the bought amount.

## What the swap layer does

Every swap is gated to a single approved external swap aggregator. Any other target is rejected at the contract level. Slippage protection is enforced one layer up — the router enforces a minimum acceptable output for user swaps, and the strategy allocator enforces a minimum acceptable output for reward-compound swaps.

<Warning>
**The swap target is hard-validated against the configured aggregator.** Any other target reverts. This prevents a caller from being tricked into routing a swap through an arbitrary contract via crafted swap data.
</Warning>

Only the router and the strategy allocator can trigger a swap; no other path exists.

## Why an external aggregator

Tumbuh routes swaps through a third-party aggregator (currently 0x) rather than calling individual market contracts directly. Two reasons:

- **Best-execution routing.** The aggregator finds competitive pricing across markets, so the same input gets a good rate without Tumbuh maintaining its own routing logic.
- **Minimum attack surface.** The swap layer has a single external dependency, which keeps the surface area for bugs small.

The price quality of any individual swap depends on the aggregator's quote at submission time. Slippage protection is the responsibility of the caller.
