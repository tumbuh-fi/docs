# SwapContract

The SwapContract is a small adapter for the [0x API v2 AllowanceHolder](https://0x.org/docs/api). The Router uses it for IDRX↔USDC; the StrategyManager uses it for converting reward tokens to USDC during `claimAndCompound`. No other contract can call it — `fillQuote` is gated by `onlyAuthorized`, restricted to those two callers.

The contract is deliberately thin. It does not choose what to swap, when to swap, or hold funds between calls. It validates the swap target, executes the call, and returns the bought amount.

## `fillQuote`

```solidity
function fillQuote(
    address sellToken,
    address buyToken,
    uint256 amount,
    address swapTarget,
    bytes calldata swapCallData
) external onlyAuthorized nonReentrant returns (uint256 boughtAmount);
```

| Parameter | Meaning |
|---|---|
| `sellToken` | Token to sell (IDRX, USDC, or a reward token). |
| `buyToken` | Token to receive. |
| `amount` | How much `sellToken` to sell. |
| `swapTarget` | Must equal the configured `allowanceHolder` address. Other targets are rejected. |
| `swapCallData` | Opaque calldata fetched from the 0x API for this specific quote. |

The contract pulls `amount` of `sellToken` from the caller, approves the AllowanceHolder, executes `swapTarget.call(swapCallData)`, resets the approval, and transfers the resulting `buyToken` back to the caller. Returns the actual `buyToken` received.

<Warning>
**`swapTarget` is hard-validated against the configured `allowanceHolder`.** Any other target reverts. This prevents a caller from being tricked into routing a swap through an arbitrary contract via crafted `swapCallData`.
</Warning>

## Authorization

```solidity
modifier onlyAuthorized() {
    if (msg.sender != strategyManager && msg.sender != router) revert NotAuthorized();
    _;
}
```

The Router and the StrategyManager are the only authorized callers. There is no other path into `fillQuote`.

## Owner functions

The SwapContract uses `Ownable` (single-owner) rather than `AccessControl`. Two owner-only functions exist:

| Function | Effect |
|---|---|
| `setStrategyManager(address _strategyManager)` | Updates the authorized StrategyManager. Emits `StrategyManagerUpdated`. |
| `setRouter(address _router)` | Updates the authorized Router. Emits `RouterUpdated`. |

The owner cannot call `fillQuote` directly — owner authority is for configuration only.

## Events

| Event | Notes |
|---|---|
| `SwapFinished(sellToken, buyToken, boughtAmount)` | Fires on every successful swap. Indexers can attribute the swap to its caller via the transaction context. |
| `StrategyManagerUpdated`, `RouterUpdated` | Configuration changes. |

## Why 0x

Tumbuh swaps go through 0x rather than calling a DEX directly. Two reasons:

- **Best-execution routing.** 0x aggregates across DEXs, so the same input gets a competitive price across pools without Tumbuh maintaining its own routing logic.
- **Minimum attack surface.** The SwapContract has one external dependency (the AllowanceHolder). It does not call DEX pools, oracles, or token-specific logic.

The price quality of any individual swap depends on 0x's quote at submission time. Slippage protection is the responsibility of the caller — the Router enforces `minSharesOut`/`minIdrxOut` at the user-facing layer, and the StrategyManager enforces `minUsdcOut` during `claimAndCompound`.
