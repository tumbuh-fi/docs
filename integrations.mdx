# Integrations

Tumbuh's StrategyManager allocates USDC across multiple external yield protocols. This page lists the protocols integrated at launch and explains the integration philosophy. The companion [Add a new protocol](/integrations-add-new-protocol) page covers the operational steps to add another one.

## Integration philosophy: any ERC-4626

Tumbuh integrates external yield through a generic adapter pattern. Any vault that implements the [ERC-4626](https://eips.ethereum.org/EIPS/eip-4626) standard correctly can be added as a strategy without writing new code — registration uses the existing `GenericERC4626Strategy` adapter. The only time a custom adapter is needed is when a protocol pays reward tokens through a non-standard distributor (Morpho's Universal Rewards Distributor is the current example).

This is intentional. The protocol's strategy set can grow without contract upgrades, and the trust boundary is the same for every strategy: the StrategyManager calls a small, gated interface (`handleDeposit`, `handleWithdraw`, `convertToAssets`, `handleClaimExtraReward`).

## Per-protocol notes

### Morpho

Morpho is integrated at two distinct vault addresses for diversification across Morpho's underlying markets. Each vault is its own ERC-4626 instance with its own risk profile, and both share the `MorphoStrategy` adapter.

The `MorphoStrategy` adapter inherits from `GenericERC4626Strategy` and adds one method: `handleClaimExtraReward`. This method calls Morpho's [Universal Rewards Distributor (URD)](/glossary#universal-rewards-distributor-urd) with a Merkle proof to claim accrued MORPHO rewards. The StrategyManager's `claimAndCompound` then swaps MORPHO to USDC and re-deposits — see the [reward compounding section](/protocol-architecture/strategy-manager#reward-compounding).

For Morpho's own protocol documentation, including market-level risk parameters, see [docs.morpho.org](https://docs.morpho.org/).

### AutoFinance

AutoFinance is integrated as a plain ERC-4626 vault through `GenericERC4626Strategy`. No reward token, no Merkle proofs, no special handling. Yield reaches the Vault entirely through `convertToAssets` rising over time.

For AutoFinance's own documentation, see the protocol's published resources.

### Avantis

Avantis is integrated as a plain ERC-4626 vault through `GenericERC4626Strategy`. Same shape as AutoFinance from Tumbuh's perspective: deposit, hold, redeem. No reward token, no special handling.

For Avantis's own documentation, see the protocol's published resources.

## Allocation lifecycle

Allocations are not static. The Operator can:

- **Add a strategy** with `addFarmStrategy(adapter, vault, percentage)`. The new percentage is part of the 10000 bps budget.
- **Update percentages** with `updateStrategyPercentages(ids, percentages)`. Triggers an internal rebalance.
- **Remove a strategy** with `removeFarmStrategy(strategyId)`. Withdraws all funds and redistributes the percentage budget.
- **Rebalance toward targets** with `rebalance()`. Two-phase: pull from over-allocated, deposit to under-allocated.
- **Emergency-exit** a misbehaving strategy with `emergencyWithdrawStrategy(strategyId)` — Guardian-only.

See [StrategyManager](/protocol-architecture/strategy-manager) for the full lifecycle and the state diagram.

## Adding new protocols

The barrier to integrating a new protocol is intentionally low:

- If the protocol exposes an ERC-4626 vault and pays no reward tokens, no new contract code is needed. The Operator registers the vault as a strategy on the existing `GenericERC4626Strategy` adapter.
- If the protocol pays rewards through a custom distributor, a new adapter contract extends `GenericERC4626Strategy` and overrides `handleClaimExtraReward`. The new adapter is deployed behind an ERC1967Proxy and registered separately.

Operational checklist: [Add a new protocol](/integrations-add-new-protocol). Developer walkthrough: [Adapter guide](/developers/adapter-guide).

## Risk reminder

External protocol risk is one of the largest residual risks for Tumbuh depositors. Diversification across multiple strategies reduces exposure to any single protocol but does not eliminate it. A failure in any integrated protocol translates to a proportional loss for Tumbuh holders. See [Risks and disclosures](/security/risks-and-disclosures#external-protocol-risk).
