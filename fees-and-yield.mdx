# Fees and yield

This page covers how the vault accounts for yield, why withdrawal slippage is isolated to the withdrawer, and where the fee model stands today.

## How the vault accounts for yield

The vault's value is the sum of any idle stablecoin held in the vault plus the current value of every active yield-protocol position. If a single integrated protocol is temporarily unable to report its value, the vault falls back to the last known value for that position; this keeps the vault's reported value stable even if one external integration goes through a hiccup.

Each share's value (the vault's value divided by the share count) rises as yield accrues — see [Yield generation](/how-it-works/yield-generation) for the long-form picture.

## Slippage isolation

When the vault redeems a yield-protocol position to fund a withdrawal, the protocol may pay out slightly less than its quoted value (because of withdrawal fees, looped-position unwinding, or rounding). Tumbuh isolates this cost to the user who triggered the withdrawal. Their proceeds are reduced; other holders' position value is unaffected.

This is fair: the user who triggered the exit pays the cost of that exit, and other users are not asked to subsidise it. It is also a reason to set a realistic slippage bound when withdrawing — a bound set too tight will cause the transaction to revert; a bound set too loose accepts more cost from market movement.

For the user-facing presentation of this behaviour and a worked example, see the [Withdraw flow](/how-it-works/withdraw-flow#why-your-output-may-differ-slightly-from-the-estimate).
