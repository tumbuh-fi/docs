# Scripts and tooling

Tumbuh ships with a set of Foundry scripts for deployment and operations. They live under `script/` in the repository. This page summarizes what each script does and when you would run it.

## Foundry scripts

| Script | Purpose | Typical caller |
|---|---|---|
| `Deploy.s.sol` | Deploys the full protocol — Vault, Router, StrategyManager, SwapContract, both adapters, and TIDRX — and wires the cross-references. Registers the launch strategy set (Morpho ×2, AutoFinance, Avantis) at 10/10/40/40. | Initial deployer (one-time). |
| `Upgrade.s.sol` | Deploys new implementations and upgrades the four core proxies. | `DEFAULT_ADMIN_ROLE` holder during a planned upgrade. |
| `GrantRoles.s.sol` | Grants `OPERATOR_ROLE`, `GUARDIAN_ROLE`, `ADMIN_MANAGER` to the operator, guardian, and admin-manager addresses respectively. Run after deployment, once the role-holder addresses are finalized. | Initial deployer or `DEFAULT_ADMIN_ROLE`. |
| `PauseAll.s.sol` | Pauses Vault, StrategyManager, and Router in sequence. Use during incident response. | `GUARDIAN_ROLE`. |
| `UpdateMorphoVaults.s.sol` | Helper for switching one of the registered Morpho strategies to a different Morpho vault. Wraps `updateFarmStrategy` with the right arguments. | `OPERATOR_ROLE`. |
| `DepositWithSwap.s.sol` | Manual deposit example. Reads addresses from environment, fetches a 0x AllowanceHolder quote via `vm.ffi`, submits `depositWithSwap`. | Anyone (test or production). Requires `ZEROX_API_KEY` and a wallet with IDRX. |
| `RedeemWithSwap.s.sol` | Manual redeem example. The inverse of `DepositWithSwap.s.sol`. | Anyone holding tIDRX. |
| `CalculateStorage.s.sol` | Verifies the ERC-7201 namespaced storage slot constants in each contract match the expected hash. Run as a sanity check after any storage struct change. | Developer. |

## Environment variables

Each script reads a subset of these from the environment:

| Variable | Purpose | Required for |
|---|---|---|
| `BASE_MAINNET_RPC_URL` | Base mainnet RPC endpoint | Every script |
| `PRIVATE_KEY` | Signer private key | Deployment, role grants, upgrades |
| `ZEROX_API_KEY` | 0x API key for swap-data fetching | DepositWithSwap, RedeemWithSwap |
| `ETHERSCAN_API_KEY` (BaseScan) | For `--verify` | Deploy, Upgrade |
| `IDRX_ADDRESS`, `USDC_ADDRESS` | Token addresses | Deploy |
| `ALLOWANCE_HOLDER` | 0x AllowanceHolder address | Deploy |
| `MORPHO_VAULT`, `MORPHO_VAULT2` | Morpho strategy targets | Deploy |
| `AUTO_VAULT`, `AVANTIS_VAULT` | Other strategy targets | Deploy |
| `TREASURY_ADDRESS` | Performance-fee recipient | Deploy |
| `PERFORMANCE_FEE_BPS` | Initial fee in bps (0–3000) | Deploy (optional; defaults to 0) |
| `OPERATOR_ADDRESS`, `GUARDIAN_ADDRESS`, `ADMIN_MANAGER_ADDRESS` | Role recipients | GrantRoles |

## Running a script

```bash
forge script script/Deploy.s.sol \
  --rpc-url $BASE_MAINNET_RPC_URL \
  --broadcast \
  --verify \
  --ffi
```

`--ffi` is required for the deposit and redeem scripts because they shell out to fetch 0x quotes. Other scripts do not need it.

## Local testing

For integration testing without spending real funds, fork Base mainnet:

```bash
forge test --fork-url $BASE_MAINNET_RPC_URL --ffi -vvv
```

The test suite uses real Base addresses for IDRX, USDC, and the four external vaults. New tests should follow the patterns in `test/Integration.t.sol` and `test/Base.t.sol`.
